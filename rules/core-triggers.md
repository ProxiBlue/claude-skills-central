# Rule triggers — on-demand loading (always-on core)

Full rules live in `claude-skills-central/rules/reference/` (host: `~/claude-skills-central/rules/reference/`, container: `/var/www/html/.claude/rules/reference/`). Each carries `paths:` frontmatter — the harness auto-attaches it when you read a matching file (PHP files → php-debugging, .py files → python-debugging, logs/test-results → investigation, composer.json → upgrade-verification, pyproject.toml/uv.lock → python-upgrade-verification, plan files → hcf-plan-orchestrate). When a trigger below hits and the rule has NOT auto-attached (host sessions, non-matching flows), Read it manually BEFORE acting. Hooks enforce the mechanical parts regardless.

| Trigger | Action |
|---|---|
| Test fails, system errors, user reports bug | Read `investigation.md` FIRST. Blast radius (`git diff --stat HEAD`) before any hypothesis. Claim without artefact cite = banned. (Test failures also auto-inject compact protocol via hook.) |
| About to background a command you need the result of (`&`, `nohup`), or to write any `pgrep`/`kill -0`/marker-file wait loop | Read `background-tasks.md`. Don't. Run it in the foreground with a Bash `timeout`; if it won't fit, narrow the run. `background-wait-guard.sh` blocks both shapes. Subagents lacking `Monitor`/`BashOutput` must hand the run back to the orchestrator, never poll. |
| Playwright test timeout/failure, editing `.spec.ts`/`.page.ts`/`playwright.config.ts` after one | Read `playwright-debugging.md` FIRST. Open `trace.zip`, cite the actual failure line, before editing the test — `playwright-trace-guard.sh` blocks the edit otherwise. Mage-OS 3.3.0+ admin grids: known bulk-edit-panel phantom-row gotcha documented there. |
| PHP runtime question (wrong value, wrong branch, null return) | Read `php-debugging.md`. xdebug-mcp tools, never var_dump — hook blocks debug-call edits. |
| Python runtime question (wrong value, wrong branch, None return) | Read `python-debugging.md`. Bugsink → `pytest -l --tb=long` → `mcp-debugger` MCP (debugpy). Never print/breakpoint/pdb in `src/` — `python-debug-guard.sh` blocks the edit. |
| About to conclude scale, volume, age profile or distribution of real data ("only N rows", "nothing older than X", "no customer hits this") to justify or skip a change | Dev DB lies about scale — never reason from it. Do NOT query live to fill the gap. Use only what's already on disk (e.g. a project `prod-shape` file, counts only); if that can't answer it, state the gap and DEFER the decision to the owner. (pvcpipesupplies #462: dev 1,607 quotes vs prod 22,962.) |
| Runtime/uncaught error, or one you cannot re-run (cron, queue, uat/live, a customer's request) | **Ask Bugsink before grepping `var/log`** — it already holds the exception chain + frames. One project PER ENVIRONMENT, so a wrong id silently answers the wrong question. Queries + ids: that repo's `.claude/bugsink.md`; protocol: `investigation.md`. **Then the log server** for the same window: `logs-uat` / `logs-prod` MCP (status/latency per URL, nginx/fpm/slow logs, Magento var/log) — queries in `.claude/logs.md`. Never SSH to uat/live for logs. |
| Landed a runtime-behaviour change outside an HCF batch | Sweep Bugsink for issues `first_seen` since the work started — the errors nobody reported (`investigation.md` → Hidden issues). Inside an HCF batch `issue-sentinel` already does this post-batch; don't duplicate. |
| Magento/Mage-OS upgrade, version bump, new module | Read `upgrade-verification.md` BEFORE any "verified" claim. Admin checkout + custom-module specs + golden path, all enumerated + run. |
| Python dependency bump (`pyproject.toml`, `uv.lock`, `requirements*.txt`) or Python version bump | Read `python-upgrade-verification.md` BEFORE any "verified" claim. Full suite + ruff + basedpyright + pip-audit + re-exported requirements.txt + booted app. |
| Plan orchestration (Magento or Python) | Read `hcf-plan-orchestrate.md` first. `/pb-hcf:wire` before `/hcf:plan-orchestrate` (Python: `--stack=python`, no codegraph/xhgui playbooks); legacy pipeline.md = stop. |
| Posting ticket comment | Hook forces `gh-comment-hidden.sh`. ≤5 lines, caveman, status prefix. Reference: `gh-ticket-comments.md`. |
| Any web page fetch — security scan, research, "what does this page say" | `webfetch-completeness-guard.sh` blocks WebFetch outright (blanket, not just security). Use `curl` raw (or raw browser-tool text extraction for JS/auth pages) and read the FULL output — never a summarized preview. Reference: `completeness-critical-fetch.md`. |
| New DDEV PHP project onboarding, `webimage_extra_packages` with `phpX.Y-pcov`, or a `ddev xdebug on` / `xdebug_enabled: true` post-start hook found in `.ddev/config.yaml` | Read `xdebug-pcov-defaults.md`. xdebug/pcov must default OFF in both FPM and CLI — FPM crashes with SIGSEGV under load if xdebug is loaded; CLI just pays a needless speed tax (xdebug-mcp self-heats on demand, no always-on needed). |

Per-project rule opt-out: `<repo>/.claude/rules-disable`, one hook name per line (`python-debug-guard`, `gh-comment-guard`, `php-debug-guard`, `test-failure-context`, `git-tree-guard`, `webfetch-completeness-guard`, `background-wait-guard`). Prose rules vary per project via that project's root CLAUDE.md include list.
